# План сдачи

## Что требует задание буквально

- Публичный GitHub-репозиторий с кодом.
- Один отчёт в Markdown или TeX.
- Лучший adapter или checkpoint в открытом Hugging Face-репозитории.

Отдельный отчёт по каждому методу не требуется. Для воспроизводимости остаются
JSON, logs и HTML-диагностика, но выводы и ключевые изображения входят в общий
`REPORT.md`.

## Как должен выглядеть репозиторий

### `README.md`

- Что решается и какой метод выбран.
- Как установить зависимости.
- Как получить или собрать данные.
- Как обучить модель одной командой.
- Как воспроизвести evaluation и фигуры одной командой.
- Ссылки на `REPORT.md`, финальный HTML и Hugging Face checkpoint.
- Ожидаемое время, устройство и объём диска.

Текущий `README.md` описывает старый SAE/MLflow pipeline и не воспроизводит общий
screening. Его нужно заменить после выбора финального метода.

### `REPORT.md`

- Краткий ответ на вопрос задания.
- Зафиксированный evaluation contract.
- Naive, MSE и GLP baselines.
- Финальный метод и его отличие от baselines.
- Главный Pareto-front.
- Decoded examples и failure cases.
- Causal ablations, объясняющие механизм.
- Стоимость inference.
- Ограничения и отрицательные результаты.
- Ссылка на checkpoint и точные команды.

Текст короткий. Один абзац делает один вывод. Каждому важному выводу соответствует
одна таблица, фигура или causal ablation.

### Финальный код

Нужно оставить один общий путь и переиспользовать существующие файлы:

- `steering.py`: модель, directions, hook, generation и metrics;
- `denoiser.py`: только архитектуры финальных baselines и выбранного метода;
- `train_denoiser.py`: один training entry;
- `eval_steering.py`: один общий evaluation entry;
- `viz.py`: сборка финальных фигур и HTML;
- `run_steering.sh`: последовательный воспроизводимый запуск;
- `requirements.txt` и `setup.sh`: установка среды;
- `tmp/`: эксперименты, не входящие в основную линию.

Перенос из `tmp/` начинается после выбора финального метода. Неудачные прототипы
не должны усложнять основной training path.

### Финальные артефакты

- `runs/final/metrics.json`: все значения и интервалы основной таблицы;
- `runs/final/report.html`: интерактивное приложение;
- `runs/final/figures/`: изображения, встроенные в `REPORT.md`;
- `runs/final/config.json`: эффективная конфигурация;
- `runs/final/provenance.json`: commit, data revisions и checkpoint hashes;
- `logs/final_train.log` и `logs/final_eval.log`: полные логи.

Checkpoint не хранится в Git. В Git остаются ссылка, config, hash и model card.

### Hugging Face

Открытый репозиторий содержит:

- лучший checkpoint;
- `config.json`;
- нормализацию активаций;
- model card с данными, слоем, direction-independent training и примером inference;
- ссылку на Git commit, который создал checkpoint.

## Что мешает финальной отправке

### 1. Исправить evaluation contract

- Проверить identity при \(\alpha=0\) для каждого repair.
- Считать неопределённость по prompts, а не считать продолжения независимыми.
- Зафиксировать правило matched-property сравнения.
- Решить, достаточно ли SST-2 property или нужна независимая проверка.
- Решить, нужен ли второй validation direction.

### 2. Отделить валидные методы от сломанных прототипов

- Curveball нельзя ранжировать по текущему запуску: kernel-step неверно
  откалиброван, training и inference activations не совпадают, большие \(\alpha\)
  схлопываются в одно состояние.
- UniSteer и INNSteer нельзя переносить в финал без проверки их training objective,
  насыщения и соответствия первичным статьям.
- Методы, которые не прошли эту проверку, остаются в приложении без claims.

### 3. Выбрать финалистов

Обязательный набор: naive, простой MSE из задания и GLP.

Дополнительный набор: `[DECISION: один или два метода после исправленного
Mac-screening]`.

Выбор делается по Pareto, decoded failures, устойчивости и latency. Training loss
не является критерием выбора.

### 4. Провести финальные A100-запуски

- Обучить финалистов на согласованном полном объёме FineWeb activations.
- Использовать заранее зафиксированные seeds.
- Не менять prompts, \(\alpha\)-grid и метрики после просмотра результатов.
- Сохранить best и final checkpoints с полной provenance.
- Повторить общий evaluation для всех финалистов.

### 5. Собрать доказательства для отчёта

- Главный Pareto-front показывает только финалистов.
- Основная таблица сравнивает методы при matched property.
- Decoded panel показывает типичный выигрыш, проигрыш и failure case.
- Mechanism panel показывает steering coordinate, correction и downstream effect.
- Ablation table меняет по одной части метода.
- Latency plot показывает стоимость улучшения.
- Полный screening остаётся приложением и не скрывается.

Кривые обучения входят только как подтверждение сходимости и выбора checkpoint.
PCA, singular values и kNN входят только там, где отвечают на конкретную
геометрическую гипотезу.

### 6. Подготовить чистый запуск

- Свести одобренный код из `tmp/` в существующие основные модули.
- Удалить из README старые команды, которые больше не соответствуют решению.
- Запустить unit tests.
- Проверить setup в чистой среде.
- Воспроизвести одну короткую CPU или MPS smoke-проверку из README.
- Проверить, что финальные фигуры собираются из `metrics.json`, а не вручную.

### 7. Опубликовать

- Заполнить все `[RESULT]`, `[FIGURE]`, `[TABLE]`, `[HF]` и `[DECISION]` в
  `REPORT.md`.
- Проверить ссылки и изображения на GitHub.
- Загрузить лучший checkpoint в Hugging Face.
- Добавить Hugging Face URL и commit hash в README и отчёт.
- Сделать GitHub-репозиторий публичным.

## Правило для финальных изображений

Главный текст не отправляет читателя изучать dashboard. Каждая фигура находится
рядом с выводом, который она проверяет.

Фигура показывает только нужные методы и нужные оси. Полные данные доступны по
ссылке рядом. Неудобные точки не удаляются: они остаются на основной фигуре, если
меняют вывод, либо в явно названном полном приложении, если не относятся к этому
вопросу.

Подпись отвечает на три вопроса: что сравнивается, куда смотреть и какой вывод
поддерживают данные. Декоративные PCA и длинные наборы одинаковых loss curves в
финальный отчёт не входят.
